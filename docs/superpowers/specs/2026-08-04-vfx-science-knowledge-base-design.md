## 1. 目标与读者

面向 **VFX 特效师 / 技术美术（TA）** 的三学科知识梳理页面：**特效中用到的数学、物理与图形渲染**。

- 从最基础的概念讲起，循序渐进到高阶原理
- 核心写作约束：**大部分人看得懂**（先直觉后公式）、**有兴趣学下去**（现象开场、演示好玩）
- 每个知识点落到特效工具语境（Niagara / Houdini / UE 材质里对应的概念和参数）
- 图形渲染分栏的知识体系参考 LearnOpenGL、《Unity Shader 入门精要》、《Real-Time Rendering》，但按特效师的关注点重排

语言：中文正文，专业术语保留英文（如 Dot Product、Curl Noise、PBR、Alpha Blending）。

## 5. 模块内容模板（每模块统一五段式）

每个模块严格按以下顺序组织，保证循序渐进的节奏：

1. **现象**（约 100 字）— 生活化或影视/工具中的具体现象开场，提出疑问。例（物理）：*"雨滴从两千米高空落下，如果只受重力，落地时速可达 200 m/s——足以击穿头骨。但现实中的雨是温柔的。中间发生了什么？"* 例（数学）：*"为什么美术把灯光转个角度，模型就'立体'了？背后只是一个乘法。"*
2. **直觉**（约 150 字）— 用比喻把核心机制讲清，零公式。
3. **原理**（约 200-300 字）— 核心概念 + 关键公式。公式出现时必须逐项解释符号含义和直觉对应；优先文字叙述，公式只放真正关键的那一两个。
4. **交互演示** — WebGL 演示卡片（见 §6），卡片上方一句引导语（如"试试把阻力系数拉到最大，看雨滴如何悬停"）。
5. **应用到特效**（约 100 字）— 该知识在特效工具中的对应：Niagara / Houdini / UE 材质里的节点或参数名，以及特效师常踩的直觉误区。数学/渲染模块同样落在特效语境。

写作红线：
- 禁止堆砌教科书式推导；每个公式必须有"人话翻译"
- 比喻必须贴近日常（电梯、滑板、吹蜡烛），不用读者不熟悉的喻体
- 每模块结尾不写"总结"段，直接收在应用段
- 交叉引用只在真正降低理解成本时加，每模块最多 2 处

## 6. WebGL 交互演示

### 6.1 技术方案

- **原生 WebGL2**（回退 WebGL1），不引入 three.js 或任何第三方库（离线约束）
- 自研一个小型共享渲染框架（约 400-600 行），提供：
  - 点精灵粒子渲染（位置/颜色/大小 buffer，逐帧 CPU 物理积分后上传）
  - 全屏四边形 pass（供 shader 类演示使用：流体、Metaball、噪声、光照球）
  - 线段渲染（轨迹、弹簧链、闪电枝干、向量箭头）
  - 简单网格渲染（带法线的球体/平面，供光照与 PBR 演示使用）
  - 画布尺寸自适应（devicePixelRatio 感知，ResizeObserver）
- 每个演示 = 一个独立 `Demo` 对象（init / update(dt, params) / render），注册到统一调度器
- **流体类演示（P07/P08）**：CPU 端粗网格求解（约 96×96 Stable Fluids），每帧把速度/温度场上传为 GPU 纹理渲染——避开浮点渲染目标（float FBO）的兼容性深坑，96×96 的 CPU 开销在中端机器上可忽略
- **光照类演示（R05-R12）**：统一"光照球"场景（一个球体 + 可调光源），不同模块切换着色器与参数，保持视觉连续性
- **懒初始化**：IntersectionObserver，进入视口才创建 GL context 并开始 rAF 循环；离开视口超过一屏暂停 rAF
- **活跃演示上限 2 个**：演示卡片高度约 400px，常规视口最多两个同屏；超过上限时暂停最早激活的演示。粒子规模按中端核显 60fps 预算设计（见 §6.3 各演示的量级）
- **非激活栏的演示全部暂停**（标签页切换时）

### 6.2 参数面板

每个演示卡片下方一组滑杆（`<input type="range">`，杂志风样式），2-4 个参数，实时生效。每个滑杆有标签和当前数值。另配一个"重置"按钮恢复默认参数。不含画布点击/拖拽类交互（保持纯滑杆模型）。

| R12 | IBL 环境反射 | 光照球在程序化环境下的反射随粗糙度变化 | 粗糙度、环境亮度 |
| R13 | UV 映射 | 2D UV 网格 ↔ 3D 面贴图的双视图联动 | UV 缩放/平移 |
| R14 | Mipmap | 透视地面棋盘格纹理，开/关 mipmap 对比摩尔纹 | mipmap 开关、相机远近 |
| R15 | Z-Buffer | 半透明剖视看深度缓冲值，物体前后移动 | 物体深度、深度可视化开关 |
| R16 | 混合排序 | 多层半透明面片，不同混合模式与排序正误对比 | 混合模式、排序开关 |

### 6.4 演示容错

- WebGL 不可用（或 context 创建失败）时：演示区显示样式化的静态占位框 + 一句文字说明"此演示需要支持 WebGL 的浏览器"
- 物理积分使用半隐式欧拉 + 帧时间钳制（dt ≤ 32ms），避免后台切回时爆掉

## 7. 视觉设计规范（科学杂志 · 编辑风）

### 7.1 色彩

| Token | 值 | 用途 |
|---|---|---|
| `--paper` | `#FAF7F0` | 页面底色（暖纸白） |
| `--ink` | `#1A1815` | 正文与标题 |
| `--ink-soft` | `#4A453D` | 次要文字、图注 |
| `--accent` | `#B4552D` | 唯一强调色（砖红）：章节号、链接、高亮、滑杆拇指 |
| `--hairline` | `#D8D2C4` | 分隔细线、演示卡片边框 |
| `--demo-bg` | `#12100D` | 演示画布背景（深色，让粒子/光效清晰） |

演示画布用深色底（纸面上的"暗窗"），与正文亮底形成对比，也让光效类演示观感正确。

### 7.2 排版

- 正文列宽 `68ch`，居中；正文 17px / 行高 1.8
- 标题层级：H1 栏名（衬线 40px+）、域/层扉页标题（衬线 32px）、模块标题（衬线 24px，配砖红小字编号如 `M02` / `P07` / `R10`）
- 公式：衬线斜体风格块，居中，浅纸色底 + 细边框
- 正文与演示卡片间距 ≥ 48px；模块之间间距 ≥ 96px
- 段落不用首行缩进，段间距 1em

### 7.3 动效（克制）

- 模块标题、演示卡片进入视口时轻微淡入上移（300ms ease-out），尊重 `prefers-reduced-motion`
- 目录当前项高亮切换用 200ms 过渡；标签页切换用 150ms 淡入，不做滑动
- 不做视差、不做装饰性动画

## 8. 布局与导航

- **顶部标签栏**（sticky）：站点名 + 数学 / 物理 / 图形渲染三个标签 + 当前栏阅读进度条（砖红细线）
- **单栏长文**：每栏居中正文列（max-width 约 720px）
- **右侧浮动目录**：≥1180px 视口时显示，`position: sticky` 跟随，按"域/层 → 模块"两级列出当前栏全部模块，IntersectionObserver 驱动当前项高亮；点击平滑滚动跳转
- **窄屏（<1180px）**：浮动目录隐藏，顶部标签栏提供可展开的"目录"抽屉（列出同样的层级）
- 模块编号全局唯一（M/P/R 前缀 + 两位序号），目录与交叉引用均用编号定位

## 9. 可访问性与渐进增强

- 对比度：正文对纸底 ≥ 7:1；砖红强调色用于大字号/图形元素时 ≥ 3:1
- 滑杆为原生 `input[type=range]` + 可见标签，键盘可调
- 标签页为 `role="tablist"` / `role="tab"` / `role="tabpanel"` 语义，支持键盘左右切换
- 演示画布带 `aria-label` 描述演示内容
- `prefers-reduced-motion` 关闭入场动画与闪烁类效果（如闪电频闪降为单次）
- 语义化标签：`<article>` 模块、`<nav>` 目录、标题层级不跳级

## 10. 明确不做（YAGNI）

- 不做深色模式切换（单一杂志风）
- 不做国际化（仅中文）
- 不做服务端/构建流程/包管理
- 不做移动端手势交互（滑杆在触屏可用即可）
- 不做音频
- 不做用户进度持久化（localStorage 记录阅读进度不在本期范围）

## 11. 验收标准

1. 单文件离线打开，无控制台错误，无网络请求（DevTools Network 为空）
2. 三栏标签切换正常：各自保留滚动位置与演示参数状态
3. 45 个模块按五段式模板完整呈现，每个演示可拖参且实时响应
4. 交叉引用跳转卡片全部可达（点击后切栏并滚动到目标模块）
5. 演示帧率：活跃演示达到上限（2 个）时，DevTools Performance 面板实测主线程帧耗时 ≤ 16ms（基准机器在实现时记录）
6. 窄屏（375px）下布局不破、目录抽屉与标签栏可用
7. `prefers-reduced-motion` 下无入场动画
8. 中文排版符合习惯（中英文间空格、全角标点）
