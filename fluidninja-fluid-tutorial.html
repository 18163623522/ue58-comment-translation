先说清楚：我们在学什么？

先划清边界：本教程用公开的 Stable Fluids 思路，帮助你理解 FluidNinja 一类 Unreal 实时流体效果；它不是对 FluidNinja 源码的逆向说明。

FluidNinja 是面向 Unreal Engine 的实时流体工具/资产系列。它能生成可用于烟、火、液体表面与环境效果的动态数据，并把模拟、交互和材质输出组织成可用于项目的工具链。

商业产品的具体实现、优化和功能组合以官方文档及实际版本为准。本文只从公开、经典、可复现的技术路线出发：

Jos Stam《Stable Fluids》(SIGGRAPH 1999)
+ GPU Gems 第 38 章的 GPU 实现路线 它们是许多 GPU 网格流体教程和 WebGL 演示的重要技术来源
阅读口径：下文出现“FluidNinja 一类效果”时，指的是视觉目标或公开技术谱系相近，并不表示某个商业版本内部一定使用同样的通道、顺序或求解器。
一句话理解

把画面切成很多格，每格记两本账：风往哪吹，以及烟/墨有多少。

UE 对应物

网页里的“二维纹理”对应 Niagara 的 Grid2D Collection；一轮 shader 计算对应一个 Simulation Stage。

先观察什么

先看速度箭头，再看染料。速度是搬运工，染料只是乘客；不要把颜色本身误当成流体速度。

容易误解

这里的“水面”只是把染料当高度做的着色预览，不是带体积、飞溅和自由液面的真实液体。

这套算法的世界观一句话就能说完：

不追踪每一滴水，而是把空间切成网格，每个格子记录一缕"风"，然后让四个简单步骤每帧轮流上场。

四类核心操作：把一条方程拆成几件小事

流体力学的核心是纳维-斯托克斯方程（Navier-Stokes）。它看起来吓人，但拆开看每一项都是一件你熟悉的事：

// 不可压缩流体的动量方程，逐项翻译：
∂u/∂t = −(u·∇)u   −   (1/ρ)∇p   +   ν∇²u   +   f
        ① 惯性：风把风自己吹走     —— 平流（第 2 章）
                          ② 压力：挤的地方推人不挤的地方 —— 投影（第 4 章）
                          ③ 粘性：内摩擦            —— 本页省略显式求解
                                                ④ 外力：鼠标/重力/爆炸 —— splat（第 3 章）

实时实现通常做三件事：① 按效果需要简化方程——本页没有显式粘性扩散 pass，但平流插值仍会带来数值耗散；它看起来像“变黏”，却不等于真实粘性。② 把方程拆成多个步骤——数学上叫算子分裂。③ 把每个格子的相同工作交给 GPU 并行执行。省略了什么、保留了什么，应由视觉目标和性能预算决定。

把这些操作按数据依赖排好，就是本页每帧在 GPU 上执行的流程：

Formula Walkthrough · From Symbols to Grid2D
F

公式不要背：从每个符号拆到一个格子

先读连续方程在描述什么，再看实时求解器怎样把它拆成几个离散步骤。二者不是同一层，混在一起就会出现“压力就是散度”“平流就是扩散”这类误解。

∂u/∂t + (u·∇)u = −(1/ρ)∇p + ν∇²u + f
∇·u = 0 第一行：速度为什么变化；第二行：变化后的速度必须满足不可压缩约束

先认字母：它们各自住在哪里

符号数学身份白话Grid2D 中的数据
u=(uₓ,uᵧ)二维向量场每个格子的风向与风速通常存两个有符号通道，例如 RG
p标量场为了纠正速度而解出的压力通常单独一张单通道网格
ρ密度常数/场同样的压力对多重的流体产生多大加速度简化常密度求解器常吸收到系数中
ν运动黏度不同速度层之间互相拖拽的强弱需要显式扩散时才单独求解
f外力场玩家、浮力、风、涡度约束等输入Simulation Stage 中累加到速度
∇空间微分算子不是一个数，而是“向周围看差异”的操作读取左、右、上、下邻居做有限差分
最重要的阅读方法：∂u/∂t 是我们要求出的“速度变化结果”；右侧各项是造成变化的原因。公式不是让 GPU 同时完成的一行代码，实时实现会把这些原因拆成若干 pass，依次近似。

第一项：∂u/∂t —— 这个格子的速度正在怎么变

∂ 表示“只观察一个变量的变化”。∂u/∂t 的意思是：站在固定位置，观察这里的速度随时间改变多少。它不是外力，也不是单独储存的“惯性”；它是整条动量方程要算出的结果。

不要这样记

∂u/∂t = 惯性开关。

应该这样记

∂u/∂t = 左边的总结果；平流、压力、黏性和外力共同决定它。

第二项：(u·∇)u —— 为什么叫“速度搬运速度”

二维速度 u=(uₓ,uᵧ) 既决定你往哪里走，也决定沿途会读到什么速度。把这一项展开：

(u·∇)u = ( uₓ·∂uₓ/∂x + uᵧ·∂uₓ/∂y ,
 uₓ·∂uᵧ/∂x + uᵧ·∂uᵧ/∂y ) 沿当前速度方向穿过一个不均匀速度场，因此抵达新位置时速度也发生变化

“风搬运风”是好用的简称，更准确的名字是对流加速度。半拉格朗日实现不直接计算上面的导数，而是反向寻找上一帧的来源：

// 若 Velocity 的单位是“格子/秒”：
CellUV = (ExecutionIndex + 0.5) / NumCells;
BackUV = CellUV - Velocity * DeltaSeconds / NumCells;
NewValue = Sample(OldField, BackUV);

// 若 Velocity 的单位已经是“UV/秒”：
BackUV = CellUV - Velocity * DeltaSeconds;  // 不要再除 NumCells
UE 排错关键：先决定速度到底是“世界单位/秒”“格子/秒”还是“UV/秒”。公式没有错但单位混用时，常见结果就是完全不动、一步飞出画面，或者分辨率一改速度就变。

第三项：−(1/ρ)∇p —— 压力不是题目，而是纠错答案

∇p 是压力增长最快的方向，负号表示压力作用把流体从高压侧推向低压侧。但在压力投影里，通常不是先有一张“真实压力贴图”推动流体，而是：

暂定速度 u*
平流与外力之后
→
计算散度
找出哪里账不平
→
求压力 p
解出纠错方案
→
u = u* − ∇p
执行纠错

因此，散度是题目，压力是答案，减压力梯度才是执行。压力只确定到一个任意常数：整张压力场同时加 100，不改变它的梯度，也不会改变最终速度。

第四项：ν∇²u —— 黏性怎样“抹平速度差”

∇²u 是速度的拉普拉斯，可粗略理解为“邻居平均值与当前值的差”。某格比四周快很多时，黏性会让它慢下来，同时把影响传给周围。ν 越大，速度差被抹平得越快。

// 省略网格间距 h 时的离散形状：
LaplacianU = uLeft + uRight + uTop + uBottom - 4 * uCenter;
不要混淆：半拉格朗日插值也会把画面磨糊，这叫数值耗散。它的强弱随分辨率、时间步和采样轨迹变化，不能当作具有固定 ν 的物理黏性。本页为简化成本，没有显式求解这一项。

第五项：f —— 所有外部推手的总和

f = f玩家 + f浮力 + f风 + f涡度约束 + …

离散更新常写成 u* += Δt·f。Splat 的意思不是让某一个格子通知所有邻居，而是每个格子并行计算“我离输入点多远”，再决定自己加多少速度。格子会读取输入和邻域数据，所以“GPU 并行”不等于“格子之间完全没有信息交换”。

约束：∇·u = 0 —— 不是另一股力，而是一条合格线

二维散度展开为：

∇·u = ∂uₓ/∂x + ∂uᵧ/∂y正值：局部更像向外膨胀；负值：局部更像向内收缩

先把平流、外力和边界处理后的速度叫作 u*，再定义最终速度：

uⁿ⁺¹ = u* − (Δt/ρ)∇p

要求最终速度满足 ∇·uⁿ⁺¹ = 0，代入并整理：

∇²p = (ρ/Δt) ∇·u*这就是为什么“先算散度，再解压力，最后减梯度”

连续数学里可以得到无散结果；在有限分辨率、边界近似和有限次 Jacobi 下，实际只能让散度显著降低并接近零。

落到一个格子：三个必须配套的离散公式

设网格间距为 h，中心格为 C，左右上下为 L/R/T/B：

// 1. 中心差分计算散度
divC = (uR.x - uL.x + uT.y - uB.y) / (2*h);

// 2. Jacobi 更新压力
pC = (pL + pR + pT + pB - h*h*(rho/dt)*divC) / 4;

// 3. 减去压力梯度
uC -= (dt/rho) * vec2(pR-pL, pT-pB) / (2*h);

许多教学 shader 会把 h、ρ 和 dt 吸收到速度或压力的定义里，于是出现下面的归一化版本：

divC = 0.5 * (uR.x - uL.x + uT.y - uB.y);
pC   = 0.25 * (pL + pR + pT + pB - divC);
uC  -= 0.5 * vec2(pR - pL, pT - pB);
不要东拼西凑：散度、Jacobi 和梯度减除中的缩放必须采用同一套单位约定。只抄其中一段，常会得到“能动但投影不干净”的结果。

染料有自己的方程：它不是速度的一部分

∂c/∂t + u·∇c = S − Dc 可以是烟密度、染料、温度或游戏遮罩；S 是源，D 表示衰减/扩散等损失

默认情况下，速度搬运染料，染料不反过来修改速度。只有当你加入“温度产生浮力”等耦合时，染料/温度场才会影响速度场。这也是为什么切换显示模式只应该改变渲染，不能停止染料更新。

读完后用四句话自检

  • 平流预测速度和染料从哪里来，不等于扩散。
  • 散度描述暂定速度哪里不满足不可压缩条件，不等于压力。
  • 压力是由散度解出的约束答案，减去压力梯度才真正修正速度。
  • 投影之后不要再修改速度；否则刚压下去的散度可能又被制造出来。
Chapter 01 · The Notion of a Field
01

先建立直觉：什么是"场"

模拟流体有两种常见观察方式。本文采用第二种，因为它最容易和 GPU 纹理、Niagara Grid2D 对上。

思路 A：追踪每个水滴（拉格朗日 / 粒子法）

想象给每一滴水贴个标签，每帧问它："你在哪、速度多少、邻居是谁？" 这就是 SPH 粒子流体。直觉、好看，但代价昂贵：一升水有天文数字的分子，游戏中几十万粒子已属重负载，而且邻居查找、压力求解全是麻烦事。

思路 B：站在原地观测“风”（欧拉 / 网格法）— 本文的选择

反过来：把空间切成网格（比如 128 × 128 个格子），每个格子只记录一件事 —— 此刻流过这个位置的速度向量。这一整张"每格一格风向风速"的表，叫做速度场，数学上记作 u(x, t)：位置 x、时刻 t 处的一个向量。烟、墨、颜色这些"被搬运的东西"另存一张染料场。流体的一切运动，就是这两张表互相作用的循环：速度场搬运染料，物理规律修正速度场。

维度粒子法（拉格朗日）网格法（欧拉）— 本文
存储什么每颗粒子的位置和速度每个格子的速度和染料
数据结构变长数组，需要空间哈希找邻居就是几张图片（纹理）
与 GPU 的关系友好但需要间接寻址映射直接：一个像素/元素对应一个格子
细节表现粒子足够多时锐利受限于网格分辨率，偏"糊"
内存与成本随粒子数线性涨固定：只取决于网格分辨率

网格法适合 GPU 的关键在于：整个模拟状态可以装进几张纹理或网格缓冲，每一步都让大量格子并行执行相同计算。这不代表任何分辨率、任何设备都一定流畅；真实成本仍取决于网格尺寸、阶段数、迭代次数、像素格式和目标硬件。

一句话理解

Grid2D 就是一张表格。格子不移动，格子里的速度和染料数值每帧更新。

UE 对应物

Execution Index 像当前格子的行列号；把它换算成 UV，才能采样“我和我的邻居”。

Chapter 02 · Advection
02

平流：让物质跟着风走

Advection —— 整套算法里最精妙的一步，也是最反直觉的一步。

为什么"把值推走"是条死路

场有了，下一个问题：染料怎么动？最直觉的答案是前向欧拉："把每个格子的墨按速度推到下一个格子去。" 但在网格上这有两个致命问题：

  • 并行 scatter（向外写）更难组织。多个格子可能同时写到同一目标，需要原子操作、累加缓冲或额外归一化；普通像素式 pass 更适合让每个目标格子自己去旧场里“取”。
  • 一步跨多格。速度快、帧率低时，一个格子的值理论上要飞越好几个格子，中间的格子根本不知道该接多少 —— 这就是著名的 CFL 条件：显式平流要求"一步最多走一格"，否则不稳定。

半拉格朗日：倒着走一步，去上游取水

Stam 的天才翻转是反过来问："此刻停在我这格的这缕空气，上一刻在哪？" 答案很简单 —— 沿着速度倒退一小步：

采样位置 = 当前位置 − Δt × 速度(当前格子)
新值 = 旧场在"上游位置"的插值采样 —— 半拉格朗日（Semi-Lagrangian）平流

这个方向翻转把“向很多格子写值”变成了“每个格子只读一个上游位置”。对平流这一步来说，它即使不满足传统 CFL 限制也通常不会数值爆炸；但时间步太大仍会跳过细节、增加误差，稳定不等于准确，也不等于整套求解器可随意放大 dt。

// 平流 shader 的全部核心，就这三行：
vec2 v    = texture(uVelocity, vUv).xy;   // 这格的风
vec2 coord = vUv - dt * v * texelSize;         // 逆着风倒退一步 → 上游坐标
vec4 result = texture(uSource, coord);     // 去上游把值取回来

代价：数值耗散

稳定性不是白来的。插值会轻微地抹平数据：尖锐边缘变圆、小尺度旋涡逐渐消失。这叫数值耗散。它在视觉上可能像增加了黏性，因此简化演示常省略显式粘性扩散；但它依赖分辨率、时间步和采样方式，不能当作物理黏性的严格替代。第 3 章的涡度约束会补回一部分被磨掉的小尺度旋转。

试一试：① 投放染料方块，观察直角在几秒到几十秒内变圆，这就是数值耗散。② “反转采样方向”只是一个故意做错的对照：它仍是 pull sampling，不是严谨实现的前向 splat。③ 显示 96×96 模拟网格，分清“模拟分辨率”和“屏幕显示分辨率”。

Chapter 03 · Forces & Vorticity
03

给流体施力，并保住旋涡

交互可以从一次局部加力开始；涡度约束则负责把被数值耗散磨掉的旋转感补回来一部分。

外力：往场里"拍"一下

鼠标划过、角色跳进水里、爆炸冲击波 —— 在这套算法眼里全是同一件事：在速度场的某个位置，按高斯衰减加一团速度。中心加得多、远处指数归零，像手指戳水面。一次鼠标拖动 = 两个 splat（速度 + 染料）：

// splat：在 point 处按高斯衰减叠加一团"力"
vec2 p = vUv - point;
vec3 add = exp(-dot(p, p) / radius) * color;  // color = (力x, 力y, 0)
result = texture(uTarget, vUv) + add;          // 速度、染料都这么加

两个值得注意的工程细节：力的量级是"像素速度差 × 一个大系数"（本页用 6000），因为格子很小，uv 坐标下的位移数值极小，要放大才有动感；半径参数会按画面宽高比修正（p.x *= aspect），否则宽屏上"圆"会变成"椭圆"。

涡度：先给"旋转"定一个数

想保住旋涡，先得能测量旋涡。想象往格子里放一根微小的桨轮：它转不转、往哪转，就是涡度（curl）ω —— 逆时针为正、顺时针为负、静止为零。数学定义是 ω = ∂u_y/∂x − ∂u_x/∂y（"竖直速度的左右变化"减"水平速度的上下变化"），离散化就是对邻居做差分，一行代码：

// 四个邻居各借一个分量，相减得旋转强度
float L = texture(uVelocity, 左).y;  // 左边邻居的竖直速度
float R = texture(uVelocity, 右).y;
float T = texture(uVelocity, 上).x;  // 上边邻居的水平速度
float B = texture(uVelocity, 下).x;
float curl = R - L - T + B;

涡度约束：给快被磨平的旋涡"扶一把"

第 2 章说过，平流的插值像轻微的摩擦，会把小旋涡一点点磨没 —— 流体看起来"糊"、没有生气。电影游戏业的经典补丁是 Vorticity Confinement（Fedkiw 等人，1996），思路分三步：

  • 算每个格子的涡度 ω（上面的 curl）；
  • 再算 |ω| 的梯度方向 ∇|ω| —— 它指向"附近哪里转得更凶"（旋涡中心的涡度最强，梯度从弱指向强）；
  • 取 ∇|ω| 与 ω 的叉积得到一个与旋转方向相切的力，乘上强度 ε，加回速度场 —— 人为把能量还给快被耗散吃掉的涡。
F = ε · dt · ( ∇|ω| × ω )  →  u ← u + F ε 是"漩涡劲道"旋钮 —— 数值耗散的官方解药

参数手感：本页演示中，ε = 0 时小旋涡消失较快，10~20 开始明显补回旋转，30 以上会非常活跃。这个数值只对本页的分辨率、时间步和单位成立，不能直接照抄到 UE 或其他求解器。

试一试：右侧把滑块拉到 0，快速画几个圈 —— 旋涡几秒内就被"摩擦"磨平。再推到 40 画同样的圈：旋涡不但活着，还会互相吞噬、翻卷出细丝。（此演示中压力投影默认开启——把它当黑盒，下一章马上解剖。）

Chapter 04 · Projection · The Soul
04

灵魂步骤：不可压缩与压力投影

投影负责把速度场里不合理的“凭空膨胀/收缩”压下去。它很重要，但烟也常用不可压缩求解器；“水或烟”的外观还取决于密度、浮力、边界和材质。

第一环：水的一个铁律 —— 挤不动

水的不可压缩性意味着：任何一个格子，流进来多少，就必须流出去多少。把每个格子想成一个账本：四面八方的流入减流出，必须恰好等于零。这个"净流出量"有一个名字 —— 散度（divergence），记作 ∇·u：

∇·u = 0   （不可压缩条件：账必须平）

问题来了：你随手"拍"出来的速度场、被平流搬过一圈的速度场，几乎不可能恰好满足这条铁律 —— 有的格子净流出（像源），有的净流入（像洞）。真实的水会立刻用压力自救：挤的地方压力大，把自己推开；疏的地方压力小，把周围吸来。

第二环：数学一句话 —— 找一个"熨斗场"

把上面那句物理直觉翻译成数学：找一个标量场 p（压力），使得 u − ∇p 尽量接近无散度。展开这个要求，p 必须满足一个泊松方程：

∇²p = ∇·u   然后   u ← u − ∇p离散边界与有限次迭代下，修正后的散度通常是“接近零”而非精确等于零

直白解读：等式右边是"账本"（哪里不平），左边 ∇²p 是"压力的弯曲程度"。解出 p，逆着它的梯度修正速度，账就平了。压力就是把速度场熨平到不可压缩的那只熨斗。

第三环：游戏一整套 —— Jacobi 迭代

直接精确求解大规模联立方程通常不符合实时预算。一个便于 GPU 并行的教学方案是 Jacobi 迭代：给每个格子一个简单更新规则，反复刷：

// 压力 Jacobi 迭代 —— 每个格子只做一次"取邻居平均再减账"：
p(自己) = ( p左 + p右 + p上 + p下 − 散度(自己) ) / 4.0;
// 把这行刷 20~40 遍全屏，p 就收敛到足够接近真解

三个常被问到的问题，一次说清：

  • 为什么除以 4？离散的 ∇²p 在 2D 网格上就是"四邻之和减四倍的自己"（拉普拉斯的差分形式）。把 ∇²p = div 移项，就得到"自己 = (四邻之和 − div)/4"——系数不是调出来的，是代数移项移出来的。
  • 为什么通常多刷会更准？每一轮都让邻域信息继续传播；迭代太少时低频误差仍很明显。达到“视觉足够”要多少轮取决于分辨率、边界、初始猜测和容许误差，不存在通用的 40 次答案。
  • 不从零开始行不行？不但行，还更快 —— 热启动：每帧把上一帧的压力留 80% 当初始猜测。流体是连续演化的，上一帧的解和这一帧差别很小，收敛快一大截。

另外两个工程细节：游戏敢只迭代一二十次——"接近不可压缩"在视觉上已经足够真；贴边格子的法向速度取反（墙不可穿透），让撞墙的账也算得对。

无中生有：火焰与河流

前五章的演示都要你先输入。要让效果持续运动，只需加入持续的驱动源；下面用浮力和边界注入演示两种常见方式。

发动机一：浮力 —— 火焰为什么自己往上窜

火焰不需要人吹：热空气比冷空气轻，温度越高，向上的力越强。实现只要一个 pass：读温度，往速度场的 y 分量加一个正比于温度的力。温度场也不用新建纹理——直接复用染料场，把它的 R 通道当温度用（火焰模式下"颜色"就是"温度"）。

// 浮力 shader 的全部：热的地方自动获得向上的速度
float T = texture(uTemperature, vUv).x;  // 这格的温度
v.y += buoyancy * T * dt;                   // 越热升得越快
// 摇曳：两个不同频率的 sin 叠加 ≈ 廉价噪声
float sway = sin(vUv.y * 9.0 + time * 2.3) * 0.6
           + sin(vUv.y * 17.0 - time * 3.4) * 0.4;
v.x += wobble * T * sway * dt;              // 火苗左右摇的秘密

持续燃烧 = 底部几个"火源"每帧 splat 一点点温度（5 行 JS 的 emitter），温度被平流抬着往上走、又被 dissipation 慢慢冷却 —— 火苗"下粗上细、顶端熄灭"的形状是物理自己长出来的。颜色同样不是画出来的：温度映射到铁匠都认识的黑体色带 —— 暗红 → 橙 → 黄 → 白热。

试一试：右侧火焰没人碰也会持续注入温度。把浮力滑到 0，温度主要被既有速度平流并按衰减参数冷却；本演示没有显式扩散 pass。再把浮力拉高，比较上升速度。关掉点火后，观察残余温度怎样被搬运和衰减。

发动机二：持续注入 —— 河流为什么永不停

把第 3 章的 splat 从"点一下"变成"每帧都来"，就得到了河流：上游边界持续注入向右的速度（inflow），下游持续吸走能量（outflow）。水从哪来、到哪去，全是两个方向相反的"水龙头"。第 4 章的压力投影在这里兑现它的价值：注入的水必须有处可去，投影把账算平，河流才能恒定流淌而不淤积。

再放两块简化障碍：本页只把圆形区域里的速度清零，因此能演示“绕开一块区域”的直觉，但没有完整处理固体表面的法向/切向边界，也不能据此声称得到物理上准确的卡门涡街。

// 河流边界 pass：石头 + 出水口
if (在石头内) v = vec2(0.0);            // 水过不去 → 只能绕
if (vUv.x > 出水口) {
  v *= 1.0 - 0.88 * k * k;         // 阻尼吸能，防止撞墙反弹
  if (v.x < 0.0) v.x *= 0.4;         // 出水口不许倒流
}

“网格 + 持续 inflow/outflow + 障碍 + 投影”是一条通用的实时环境流体搭建思路，可帮助理解河流、熔岩或烟雾类效果；FluidNinja 产品内部如何组合这些能力，应以对应版本的官方文档为准。

工程策略一：低分辨率模拟，高分辨率显示

整条流水线的主要成本随格子数增长。实时网格流体常在较低分辨率上模拟，再由材质采样到更高分辨率的表面。双线性过滤由纹理硬件高效完成，但并非“零成本、无损”：它会平滑细节，也仍有采样与带宽成本。第 2 章的 96×96 网格开关就是这个取舍的微缩演示。

用细节损失换模拟成本 —— 实时效果中常见的取舍

工程策略二：输出材质所需的数据

游戏效果通常不只需要颜色，还需要速度、遮罩、温度、近似高度或由其推导的法线。第 5 章的“伪水面着色”只是最小示意：把染料亮度临时当高度、用梯度算法线。真实水材质仍需结合项目的表面模型、泡沫、折射和尺度定义。

工程策略三：把 2D 数据映射到 3D 世界

二维模拟结果可以通过世界坐标到场 UV 的映射，被地形材质、网格材质或投影效果采样。这样做是“用二维场驱动三维表面外观”，并不等于求解了完整三维流体。持续边界、地形约束和材质表现仍要分别设计。

本质是 2D 模拟 + 投影映射 —— 聪明的维度作弊

工程策略四：把世界事件转成场输入

角色位置、移动速度、爆炸半径或碰撞遮罩，可以先转换到场 UV，再作为局部源注入网格。它们共享“把事件写进场”的思路，但具体写入速度、密度、高度还是障碍，应由效果模型决定。

工程策略五：为什么适合 GPU

每个 Simulation Stage 都让大量格子执行近似相同的计算，符合 GPU 并行处理方式。但能否达到目标帧率必须在目标平台实测；网格分辨率、压力迭代、格式、阶段数量和同时运行的场都会影响结果。

把整套逻辑压缩成一帧

最后只记住一句：速度是搬运工，染料是乘客；所有会修改搬运工的步骤做完后，用投影把账配平。

每一帧 (dt):
  1. 注入:   交互 / inflow 写入速度与染料                         // 源
  2. 平流速度: u* = 旧u(位置 − dt·旧u)                          // 风搬运自己
  3. 附加速度: 浮力 / 涡度约束 / 障碍边界（按需）               // 都会重新制造散度
  4. 散度:   div = ∇·u*                                           // 查账
  5. 压力:   Jacobi 迭代 N 次: p = (Σ邻居 − div) / 4             // 找纠错答案
  6. 投影:   u = u* − 0.5·(pR−pL, pT−pB)                        // 最后一次改速度
  7. 平流染料: dye = 旧dye(位置 − dt·u)                        // 乘客跟随新速度
  8. 输出:   Grid2D → RT → 材质                                   // 显示层

代码里有一行神秘的 force.y *= -1.0;：∇|ω| × ω 的叉积在"y 向上"的数学坐标系里方向正确，而屏幕/纹理坐标系 y 向下 —— 不翻转的话所有旋涡会被反向加速，越转越死。坐标系约定是图形代码里最常见的隐形坑。

ε 并非越大越好：它还给系统的能量是"凭空"的，拉太高会看到旋涡违反直觉地自我增强、出现病态抖动。20~35 是安全区。

A10

散度Divergence

给每个格子记账：净流出必须为零

记账
三种格子：源、汇、合法

把格子想成账本：四面八方的流入减流出必须恰好等于零。你随手"拍"出来、被平流搬过一圈的速度场，几乎不可能刚好满足——于是需要接下来两张卡片把它熨平。（代码里贴边格子的法向速度会取反：墙不可穿透，撞墙的账也要算对。）

∇·u = 0  （不可压缩条件）
float div = 0.5 * (R - L + T - B);  // 中心差分记账
→ 去演示 4-1 的散度视图：红=源 蓝=汇，投影开启时斑点一帧消失
深入一层

这里用的中心差分（R−L 而不是 R−C）是二阶精度的：误差与格子尺寸的平方成正比，格子减半误差降为四分之一 —— 这就是为什么网格加密对投影质量的收益是超线性的。

边界处理"法向速度取反"（如左边界的 u 取 −u）等价于"墙外有一面镜像的风往回吹"，这样墙边的账天然是平的，不需要单独的边界 pass。

A11

压力泊松方程 · Jacobi 迭代Poisson / Jacobi

"取邻居平均、再减我的账"，全屏刷 N 遍

心脏
膨胀户被解出压力低谷 → 被拉回；被挤户解出压力峰 → 被撑开

数学上把账算平等价于解一个泊松方程 ∇²p = ∇·u——但真解是百万级联立方程，游戏不等它，用 Jacobi 迭代：给每个格子一个傻瓜更新规则，反复搓到接近。压力就是把速度场熨平到不可压缩的那只熨斗，迭代次数 = 熨多少下。两个工程技巧：热启动（上一帧的压力留 80% 当初始猜测，收敛快得多）和敢少迭代（"接近不可压缩"视觉上已经是水：1 次 → 果冻，40 次 → 锋利）。

p ← ( p左 + p右 + p上 + p下 − div ) / 4  × N 遍
float pressure = (L + R + B + T - divergence) * 0.25;
→ 去演示 4-1 拖"压力迭代"滑块 1 → 60，现场看质感
深入一层

Jacobi 不是唯一解法，但规则简单、适合并行。Gauss-Seidel 会使用刚更新的邻居，传统形式的数据依赖更强；共轭梯度、多重网格等方法可能更快降低误差，但实现复杂度、同步和内存模式不同，不能只按“迭代次数”横向比较。

收敛慢的根本原因：Jacobi 每轮信息只传一格，而压力的"影响范围"是全局的。多重网格的思路就是先在粗网格上把大范围趋势算平，再回细网格修细节。

A12

梯度减除 · 投影Gradient Subtract

u ← u − ∇p，账就平了

收针
算散度 → 解压力 → 减梯度，三步合称"投影"

压力算出来后，逆着压力梯度修正速度。理论连续解可以投影到无散空间；离散边界和有限次 Jacobi 迭代下通常只能让散度显著降低。烟与水都可使用不可压缩投影，最终观感还取决于其他物理和渲染步骤。

u ← u − ∇p  ⇒  ∇·u ≈ 0
velocity.xy -= 0.5 * vec2(R - L, T - B);  // 与本文中心差分尺度匹配
→ 去演示 4-1 关掉"压力投影"，看流体立刻"漏气"
深入一层

"任何速度场都能分解成一个无旋场和一个无散场之和" —— 这是数学上的 Helmholtz 分解。投影 u ← u − ∇p 做的事，就是减掉无旋部分、留下无散部分。所以这个步骤叫"投影"：把速度投影到"所有无散场"组成的子空间上。

为什么减 ∇p 减掉的恰好是无旋部分？因为任何标量场的梯度都没有旋度（∇×∇p ≡ 0）—— 数学早在 19 世纪就铺好路了。

严格的热浮力还含一项"环境温度扣减"（T − T₀），避免全场均匀受热时整体漂移；烟囱效果的经典变体是再加一个重量项（u.y −= w·density），温度往上顶、染料往下坠 —— 烟云的翻滚感就来自这两股相反的力。

A13

法线生成Normal from Height

把染料当高度，梯度的反方向就是水面朝向

输出

如果把染料亮度人为解释成高度，就能用它的梯度构造近似法线，再做高光或扭曲。这个技巧只改变显示方式，不会把被动染料变成真实自由液面；演示 5-1 因此改名为“伪水面着色”。

n = normalize( −∂h/∂x, −∂h/∂y, k )
vec3 n = normalize(vec3((hL - hR) * k, (hB - hT) * k, 1.0));
float diff = max(dot(n, L), 0.0);
col = 基色 * (0.45 + 0.62 * diff) + 高光;
→ 去演示 5-1 切“伪水面着色”或选择“伪水面”预设
深入一层
