Chapter 00 · What Sorcery Is This
00

FluidNinja 在用什么魔法？

先把结论放在桌上：它不是粒子特效，而是一颗真正在解流体力学方程的 GPU 求解器。

FluidNinja Fluids 是 Unity / Unreal 商店里最知名的实时流体资产之一：能做沿地形流动的河流、翻涌的熔岩、被角色踩出涟漪的水面 —— 全部实时计算，全部跑在 GPU 上，甚至能和物理物体互相作用。

它是闭源商业资产，官方没有公开内部实现。但从它的表现形态（贴在地形上的连续流体、可控分辨率、与渲染管线深度集成）和技术谱系来看，它属于一个公开的、非常经典的算法家族：

Jos Stam《Stable Fluids》(SIGGRAPH 1999)
+ GPU Gems 第 38 章的 GPU 实现路线 这也是几乎所有游戏引擎实时流体（包括各种 "WebGL Fluid" 网红 demo）的共同祖先
诚实声明：本文讲的是 FluidNinja 所依托的公开经典算法，而不是对它源码的逆向。理解了这套算法，你就理解了这类资产的内核；资产本身的价值在于把它工程化、产品化的部分 —— 我们在第 7 章专门讲那部分。

这套算法的世界观一句话就能说完：

不追踪每一滴水，而是把空间切成网格，每个格子记录一缕"风"，然后让四个简单步骤每帧轮流上场。

这四个步骤，其实是把一条方程拆成了四份零钱

流体力学的核心是纳维-斯托克斯方程（Navier-Stokes）。它看起来吓人，但拆开看每一项都是一件你熟悉的事：

// 不可压缩流体的动量方程，逐项翻译：
∂u/∂t = −(u·∇)u   −   (1/ρ)∇p   +   ν∇²u   +   f
        ① 惯性：风把风自己吹走     —— 平流（第 2 章）
                          ② 压力：挤的地方推人不挤的地方 —— 投影（第 4 章）
                                        ③ 粘性：内摩擦            —— 直接扔掉（见下）
                                                ④ 外力：鼠标/重力/爆炸 —— splat（第 3 章）

游戏业的三个关键偷懒，成就了实时流体：① 粘性项直接扔掉——不是不重要，而是平流算法自带的数值耗散会免费送一点粘性（第 2 章你会亲眼看到）；② 每一项分开算、算完再合——数学上叫算子分裂，每一项单独都有一个便宜到离谱的解法；③ 全部搬到 GPU——每个格子的计算彼此独立，正是 GPU 一万个核心最擅长的事。

Chapter 01 · The Notion of a Field
01

先建立直觉：什么是"场"

模拟流体有两种截然相反的思路，FluidNinja 选了第二种。先用一张表看清楚它们差在哪。

思路 A：追踪每个水滴（拉格朗日 / 粒子法）

想象给每一滴水贴个标签，每帧问它："你在哪、速度多少、邻居是谁？" 这就是 SPH 粒子流体。直觉、好看，但代价昂贵：一升水有天文数字的分子，游戏中几十万粒子已属重负载，而且邻居查找、压力求解全是麻烦事。

思路 B：站在原地观测"风"（欧拉 / 网格法）— FluidNinja 的选择

反过来：把空间切成网格（比如 128 × 128 个格子），每个格子只记录一件事 —— 此刻流过这个位置的速度向量。这一整张"每格一格风向风速"的表，叫做速度场，数学上记作 u(x, t)：位置 x、时刻 t 处的一个向量。烟、墨、颜色这些"被搬运的东西"另存一张染料场。流体的一切运动，就是这两张表互相作用的循环：速度场搬运染料，物理规律修正速度场。

维度粒子法（拉格朗日）网格法（欧拉）— 本文
存储什么每颗粒子的位置和速度每个格子的速度和染料
数据结构变长数组，需要空间哈希找邻居就是几张图片（纹理）
与 GPU 的关系友好但需要间接寻址天生完美：一个像素 = 一个格子
细节表现粒子足够多时锐利受限于网格分辨率，偏"糊"
内存与成本随粒子数线性涨固定：只取决于网格分辨率

游戏偏爱网格法的关键一行是"与 GPU 的关系"：整个模拟状态就是几张纹理，每一步计算都是"对一张纹理的每个像素独立做同样的事"——这正好是 fragment shader / compute shader 的工作方式，一万个核心同时开工。FluidNinja 敢承诺移动端也能跑，底气就在这。

试一试：右侧演示里，先看粒子视图：几百个粒子被同一张场推动，拖尾自然织出流线。再切到箭头视图 —— 每个箭头就是一个格子里存的速度向量，你在直接看那张看不见的表。拖动鼠标，把你的"手风"刻进场里，看它如何被后来的风推着走。注意：粒子只是"记者"，删掉它们场依然存在 —— 场才是流体的本体。

这个演示用 Canvas2D 实现（CPU 上算几百个粒子绰绰有余）。从下一章开始，我们切换到真正的 GPU 网格模拟 —— 那才是 FluidNinja 的形态。

Chapter 02 · Advection
02

平流：让物质跟着风走

Advection —— 整套算法里最精妙的一步，也是最反直觉的一步。

为什么"把值推走"是条死路

场有了，下一个问题：染料怎么动？最直觉的答案是前向欧拉："把每个格子的墨按速度推到下一个格子去。" 但在网格上这有两个致命问题：

  • shader 只会"取"，不会精准地"放"。GPU 每个像素独立计算，它能把值"撒"（splat）到邻域再加权，但撒出去的权重加起来不再精确等于 1 —— 质量凭空增减，墨会越推越浓或越推越稀，数值说炸就炸。
  • 一步跨多格。速度快、帧率低时，一个格子的值理论上要飞越好几个格子，中间的格子根本不知道该接多少 —— 这就是著名的 CFL 条件：显式平流要求"一步最多走一格"，否则不稳定。

半拉格朗日：倒着走一步，去上游取水

Stam 的天才翻转是反过来问："此刻停在我这格的这缕空气，上一刻在哪？" 答案很简单 —— 沿着速度倒退一小步：

采样位置 = 当前位置 − Δt × 速度(当前格子)
新值 = 旧场在"上游位置"的插值采样 —— 半拉格朗日（Semi-Lagrangian）平流

这个方向翻转一次性解决了上面两个死穴：因为"倒退采样"永远只是在旧场里做一次插值（相邻格子取加权平均），无论速度多大、时间步多长，结果都有界 —— 不满足 CFL 也稳定，这就是 Stable Fluids 里 "Stable" 的由来。而质量虽不精确守恒，却永远不会爆炸性失衡。

// 平流 shader 的全部核心，就这三行：
vec2 v    = texture(uVelocity, vUv).xy;   // 这格的风
vec2 coord = vUv - dt * v * texelSize;         // 逆着风倒退一步 → 上游坐标
vec4 result = texture(uSource, coord);     // 去上游把值取回来

代价：数值耗散

稳定性不是白来的。插值本质是"取平均"，平均就是轻微的模糊：尖锐的边缘变圆、小尺度的涡被一点点磨掉 —— 每帧磨一点，累积起来流体就显得"糊、像蜂蜜"。这叫数值耗散，它不是 bug，反而顺便替代了 Navier-Stokes 里最贵的粘性项 ν∇²u（第 0 章说过：直接扔掉，这里免费送）。第 3 章的涡度约束就是专门来救它的。

试一试：① 右侧投一个染料方块，盯着方块的直角 —— 几分钟内变圆、变糊，这就是数值耗散在磨细节。② 勾上反转平流方向：墨立刻朝你拖动的反方向跑 —— 因为"前向采样"在 shader 里的语义是把未来位置的值取回来，方向天然是反的；这正是前向法必须用昂贵 splat 的原因。③ 勾上显示模拟网格：真正的模拟只有 96×96 个格子，丝滑画面是放大后的效果 —— 这引出 FluidNinja 的第一件工程魔法，第 7 章详述。

Chapter 03 · Forces & Vorticity
03

给流体施力，并保住旋涡

交互的全部秘密只是一个高斯函数；好看的全部秘密是一个"反耗散"补丁。

外力：往场里"拍"一下

鼠标划过、角色跳进水里、爆炸冲击波 —— 在这套算法眼里全是同一件事：在速度场的某个位置，按高斯衰减加一团速度。中心加得多、远处指数归零，像手指戳水面。一次鼠标拖动 = 两个 splat（速度 + 染料）：

// splat：在 point 处按高斯衰减叠加一团"力"
vec2 p = vUv - point;
vec3 add = exp(-dot(p, p) / radius) * color;  // color = (力x, 力y, 0)
result = texture(uTarget, vUv) + add;          // 速度、染料都这么加

两个值得注意的工程细节：力的量级是"像素速度差 × 一个大系数"（本页用 6000），因为格子很小，uv 坐标下的位移数值极小，要放大才有动感；半径参数会按画面宽高比修正（p.x *= aspect），否则宽屏上"圆"会变成"椭圆"。

涡度：先给"旋转"定一个数

想保住旋涡，先得能测量旋涡。想象往格子里放一根微小的桨轮：它转不转、往哪转，就是涡度（curl）ω —— 逆时针为正、顺时针为负、静止为零。数学定义是 ω = ∂u_y/∂x − ∂u_x/∂y（"竖直速度的左右变化"减"水平速度的上下变化"），离散化就是对邻居做差分，一行代码：

// 四个邻居各借一个分量，相减得旋转强度
float L = texture(uVelocity, 左).y;  // 左边邻居的竖直速度
float R = texture(uVelocity, 右).y;
float T = texture(uVelocity, 上).x;  // 上边邻居的水平速度
float B = texture(uVelocity, 下).x;
float curl = R - L - T + B;

涡度约束：给快被磨平的旋涡"扶一把"

第 2 章说过，平流的插值像轻微的摩擦，会把小旋涡一点点磨没 —— 流体看起来"糊"、没有生气。电影游戏业的经典补丁是 Vorticity Confinement（Fedkiw 等人，1996），思路分三步：

  • 算每个格子的涡度 ω（上面的 curl）；
  • 再算 |ω| 的梯度方向 ∇|ω| —— 它指向"附近哪里转得更凶"（旋涡中心的涡度最强，梯度从弱指向强）；
  • 取 ∇|ω| 与 ω 的叉积得到一个与旋转方向相切的力，乘上强度 ε，加回速度场 —— 人为把能量还给快被耗散吃掉的涡。
F = ε · dt · ( ∇|ω| × ω )  →  u ← u + F ε 是"漩涡劲道"旋钮 —— 数值耗散的官方解药

参数手感：ε = 0 是纯蜂蜜世界；10~20 是"烟"的自然量级；30 以上开始出现活跃湍流、旋涡互相吞噬；拉满 50 会显得"过咸"——能量强到不自然。FluidNinja 演示里那些生动的湍流感，很大程度上就是这个参数调得好。

试一试：右侧把滑块拉到 0，快速画几个圈 —— 旋涡几秒内就被"摩擦"磨平。再推到 40 画同样的圈：旋涡不但活着，还会互相吞噬、翻卷出细丝。（此演示中压力投影默认开启——把它当黑盒，下一章马上解剖。）

Chapter 04 · Projection · The Soul
04

灵魂步骤：不可压缩与压力投影

前面所有步骤都可以糊弄，唯独这一步决定了它"像水"还是"像烟"。这也是最难的一章 —— 我们把推导链一环一环拆开。

第一环：水的一个铁律 —— 挤不动

水的不可压缩性意味着：任何一个格子，流进来多少，就必须流出去多少。把每个格子想成一个账本：四面八方的流入减流出，必须恰好等于零。这个"净流出量"有一个名字 —— 散度（divergence），记作 ∇·u：

∇·u = 0   （不可压缩条件：账必须平）

问题来了：你随手"拍"出来的速度场、被平流搬过一圈的速度场，几乎不可能恰好满足这条铁律 —— 有的格子净流出（像源），有的净流入（像洞）。真实的水会立刻用压力自救：挤的地方压力大，把自己推开；疏的地方压力小，把周围吸来。

第二环：数学一句话 —— 找一个"熨斗场"

把上面那句物理直觉翻译成数学：找一个标量场 p（压力），使得 u − ∇p 恰好无散度。展开这个要求，p 必须满足一个泊松方程：

∇²p = ∇·u   然后   u ← u − ∇p修正后的 u 散度恰好为零 —— 这套操作叫"投影"（projection）

直白解读：等式右边是"账本"（哪里不平），左边 ∇²p 是"压力的弯曲程度"。解出 p，逆着它的梯度修正速度，账就平了。压力就是把速度场熨平到不可压缩的那只熨斗。

第三环：游戏一整套 —— Jacobi 迭代

真正联立求解百万个方程在游戏里不存在。GPU 上的做法是 Jacobi 迭代：给每个格子一个超简单的更新规则，反复刷：

// 压力 Jacobi 迭代 —— 每个格子只做一次"取邻居平均再减账"：
p(自己) = ( p左 + p右 + p上 + p下 − 散度(自己) ) / 4.0;
// 把这行刷 20~40 遍全屏，p 就收敛到足够接近真解

三个常被问到的问题，一次说清：

  • 为什么除以 4？离散的 ∇²p 在 2D 网格上就是"四邻之和减四倍的自己"（拉普拉斯的差分形式）。把 ∇²p = div 移项，就得到"自己 = (四邻之和 − div)/4"——系数不是调出来的，是代数移项移出来的。
  • 为什么刷得越多越准？每一轮迭代相当于信息向四周扩散一格：N 轮之后，每个格子的压力"知道"了 N 格之外的账目。全局的账要传遍画面，就得刷足够多轮 —— 这也是为什么迭代 1 次是"果冻"（只有局部修正），40 次是"水"（全局都平了）。
  • 不从零开始行不行？不但行，还更快 —— 热启动：每帧把上一帧的压力留 80% 当初始猜测。流体是连续演化的，上一帧的解和这一帧差别很小，收敛快一大截。

另外两个工程细节：游戏敢只迭代一二十次——"接近不可压缩"在视觉上已经足够真；贴边格子的法向速度取反（墙不可穿透），让撞墙的账也算得对。

试一试（本章精华，右边的演示会陪你做完）：
① 切到散度视图，拖一下：拖动边缘出现红蓝对立的斑点 —— 红是"源"（净流出），蓝是"汇"（净流入），这就是没算平的账。投影开启时它们一帧内基本消失（被熨平了）；关闭投影再拖，斑点会长期存在、越积越多。
② 回到染料视图，关掉投影：墨出现不自然的堆积斑、运动有"气体感" —— 这个世界的"水"可以被压缩了。
③ 把压力迭代滑到 1：流体质感立刻变"软"、像果冻缓慢塌陷（账只在局部被修正）；推到 40+：锋利的水感回来了。
④ 压力视图（灰度）里拖一下：亮斑是压力峰、暗斑是压力谷 —— 熨斗的工作面。

为什么是这个顺序

力放在最前：玩家的输入必须在本帧就见效，不能等风被搬运稀释之后。投影紧跟在所有"改速度"的步骤之后：涡度约束加的力会重新弄脏账本，所以要把 splat 和涡度都做完，最后统一熨一次。平流放在投影之后：搬运无散度场的误差远小于搬运一个"漏气"的场——先熨平再搬家，风才不会把墨吹出鬼影。这个顺序是 Stam 论文定下的，二十多年几乎没变过。

成本账本：为什么 60fps 毫无压力

步骤全屏 pass 数说明
外力 splat按事件数通常 < 5 个，极便宜
涡度2curl + 加力

每帧约 30~50 次全屏 pass，每次每像素只做几十次浮点运算 —— 在 GPU 上这是毛毛雨。真正的变量是网格分辨率：pass 数不变，但每个 pass 的像素数随分辨率平方增长。所以实战调优第一个动的永远是"模拟分辨率"，而不是删步骤。

Chapter 06 · Self-Driven Fluids
06

无中生有：火焰与河流

前五章的流体都要你戳它才动。但 FluidNinja 卖的是活的世界 —— 熔岩自己翻涌、河流自己奔流。秘密不是更玄的数学，而是两台"内置发动机"。

发动机一：浮力 —— 火焰为什么自己往上窜

火焰不需要人吹：热空气比冷空气轻，温度越高，向上的力越强。实现只要一个 pass：读温度，往速度场的 y 分量加一个正比于温度的力。温度场也不用新建纹理——直接复用染料场，把它的 R 通道当温度用（火焰模式下"颜色"就是"温度"）。

// 浮力 shader 的全部：热的地方自动获得向上的速度
float T = texture(uTemperature, vUv).x;  // 这格的温度
v.y += buoyancy * T * dt;                   // 越热升得越快
// 摇曳：两个不同频率的 sin 叠加 ≈ 廉价噪声
float sway = sin(vUv.y * 9.0 + time * 2.3) * 0.6
           + sin(vUv.y * 17.0 - time * 3.4) * 0.4;
v.x += wobble * T * sway * dt;              // 火苗左右摇的秘密

持续燃烧 = 底部几个"火源"每帧 splat 一点点温度（5 行 JS 的 emitter），温度被平流抬着往上走、又被 dissipation 慢慢冷却 —— 火苗"下粗上细、顶端熄灭"的形状是物理自己长出来的。颜色同样不是画出来的：温度映射到铁匠都认识的黑体色带 —— 暗红 → 橙 → 黄 → 白热。

试一试：右侧火焰没人碰它也在烧。把浮力滑到 0 —— 火苗瘫成一摊热雾（只剩扩散）；拉到 700 —— 火舌窜得又急又高。摇曳调到 0 看看"没有风的火"有多呆。关掉点火再看最后一缕热气如何飘散熄灭。

发动机二：持续注入 —— 河流为什么永不停

把第 3 章的 splat 从"点一下"变成"每帧都来"，就得到了河流：上游边界持续注入向右的速度（inflow），下游持续吸走能量（outflow）。水从哪来、到哪去，全是两个方向相反的"水龙头"。第 4 章的压力投影在这里兑现它的价值：注入的水必须有处可去，投影把账算平，河流才能恒定流淌而不淤积。

再放两块石头：圆形区域内速度清零。就这一行处理，加上投影，流体自动学会绕流 —— 水流贴着石头分开、在背后卷出成串的旋涡（流体力学里的"卡门涡街"，游戏里最漂亮的免费特效之一）。

// 河流边界 pass：石头 + 出水口
if (在石头内) v = vec2(0.0);            // 水过不去 → 只能绕
if (vUv.x > 出水口) {
  v *= 1.0 - 0.88 * k * k;         // 阻尼吸能，防止撞墙反弹
  if (v.x < 0.0) v.x *= 0.4;         // 出水口不许倒流
}

这正是 FluidNinja Live Environment 河流的内核：模拟网格 + 持续 inflow + 地形障碍（石头换成高度场）+ 投影保证守恒。换个色带就是熔岩，降低速度就是沼气。

试一试：右侧河流不需要任何人拖动。看示踪的流线绕过两块石头、在石头背后卷出旋涡。把流速从 300 拉到 2400 —— 慢速时水流温顺地贴绕，高速时石头背后的涡街狂舞（这就是涡度约束的舞台）。关掉石头对比：没有障碍的河流平得像镜子。切到水面视图：流线变成了粼粼波光。
外力的三种来源，到此集齐：交互 splat（第 3 章，你的鼠标）、浮力（火焰，温度驱动）、边界注入（河流，持续水龙头）。加上本章，你已经拥有"活的世界"的全部零件 —— FluidNinja 的环境资产无非是把这些零件与 3D 地形、引擎材质缝在一起，那是下一章的主题。

Chapter 07 · From Math to Product
07

从算法到资产：FluidNinja 的工程魔法

第 5 章的演示和 FluidNinja 卖的东西，核心是同一个。差的全是工程化 —— 而工程化正是资产的真正价值。

魔法一：在小火柴盒上算，投到 IMAX 上放

整条流水线的成本正比于格子数。FluidNinja 的思路：模拟永远在小网格上跑（一两百格的量级），渲染时把结果双线性放大到任意高分辨率。放大是"免费"的（采样时顺带插值），而流体本来就没有像素级锐利的细节，所以视觉几乎无损。第 2 章演示里那个"96×96 网格 → 丝滑画面"的开关，就是这件事的微缩版。

计算量降几个数量级，视觉几乎无损 —— GPU 流体的第一性原理

魔法二：输出的不是颜色，是材质原料

游戏里的水不能只是一张彩色贴图。FluidNinja 从模拟结果推导出法线贴图（密度的梯度 → 表面朝向）、高度、泡沫遮罩等，交给引擎的 PBR 材质：于是有了水面高光、折射扭曲、岸边泡沫。第 5 章演示的"水面法线"视图就是最小实现 —— 用染料梯度算法线再打个方向光。

魔法三：把 2D 流体"贴"上 3D 世界

FluidNinja 最招牌的能力 —— 河流沿地形流淌 —— 本体其实仍是那张 2D 模拟网格：结果纹理通过投影器 / 贴花像投影仪一样打到 3D 地形上，随表面起伏、跟随物体移动。加上"边界持续注入速度"（上游进水、下游出水 —— 第 6 章你已经亲手玩过它的内核），一条永不停的河就成立了 —— 第 4 章的投影保证这些水永远"有处可去"。

本质是 2D 模拟 + 投影映射 —— 聪明的维度作弊

魔法四：世界反过来搅动流体

角色踩水、石头落进河里怎么生效？就是第 3 章的 splat —— 引擎把物理体的位置和速度写回速度场，与你的鼠标拖动完全同一机制。脚步涟漪、船尾迹、鱼群搅水，全是同一行代码的不同参数。

魔法五：为什么必须 GPU

整条流水线是十几个全屏 pass，每个像素独立算几百次浮点运算 —— 这正是 GPU 的甜点区，百万核心并行下 60fps 毫无压力。同一规模在 CPU 上逐格循环要慢上百倍。这也是为什么这类资产在你按下 Play 之前毫无动静，按下之后整个世界活了。

本页的实现细节：速度用 RG16F（两个半精度浮点正好存 vx、vy），染料用 RGBA16F（彩色），压力/散度/涡度用 R16F（单通道就够）——存什么 field 就开什么格式，显存一点不浪费。

第二组 · 驱动与搬运 力怎么进来，东西怎么走

A3

Splat · 外力注入Gaussian Splat

高斯衰减地往场里"拍"一团力

驱动
中心力最大，距离越远指数衰减为零

鼠标划过、爆炸、角色落水——全是同一件事：在指定位置给速度场加一团力，中心强、远处指数归零，像手指戳水面。FluidNinja 里船尾迹、鱼群搅水，本质就是这个函数，只是力 F 换成了物理体的速度。

u(x) += F · exp( −|x − p|² / r² )
vec3 splat = exp(-dot(p, p) / radius) * color;  // color = (力x, 力y, 0)
result = texture(uTarget, vUv) + splat;
→ 去演示 3-1 拖一下，就是在做 splat
深入一层

radius 参数的含义是平方半径：代码里 exp(−dot(p,p)/radius) 的有效半径其实是 √radius。本页速度 splat 用 0.0025（有效半径约 5% 屏宽），染料 splat 故意再除以 2.6 —— 墨团比力团小，视觉更"笔触"。

连续拖动时每次 pointermove 都 splat 一次，两帧间隔的位移就是力向量 —— 所以"快速甩"注入的力天然比"慢慢蹭"大，无需额外处理。

A4

半拉格朗日平流Semi-Lagrangian Advection

沿着风倒退一步，去上游把值取回来

灵魂
不问"我去哪"，问"谁流进了我"

直觉做法"把每格的值按速度推走"（前向欧拉）在网格上不稳定。Stam 的翻转：问"此刻在我这格的空气，上一刻在哪？"——沿速度倒退 Δt，去那个位置采样旧值。因为永远只是插值采样，结果有界，无条件稳定、永不爆炸——这就是 Stable Fluids 的 Stable。

φ(x, t+Δt) = φ( x − Δt·u(x), t )
vec2 coord = vUv - dt * texture(uVelocity, vUv).xy * texelSize;
vec4 result = texture(uSource, coord);  // 去上游取值
→ 去演示 2-1 勾"反转平流方向"，看墨倒流（错误的前向语义）
深入一层

半拉格朗日只有一阶精度：回溯落点算得准，但取值只做了双线性插值，误差与格子尺寸成正比。追求更锐利的画面可以用 MacCormack 方案：先回溯一遍、再前向一遍、用两次结果的差修正 —— 代价是三次采样，换来接近二阶的精度。商业资产普遍在这一步做文章。

回溯的"倒退一步"用的速度是当前格的速度（不是上游的），这叫一阶显式；用"当前格与上游格速度的平均"（中点法）能显著减少大步长时的弯曲误差。

A5

双线性插值Bilinear Interpolation

落点不在格子上？找四个邻居按距离加权

搬运 · 还有第二身份
texture() 的 LINEAR 过滤自动完成

平流回溯的落点几乎不会正好落在格点上，取值就找相邻 4 格按距离加权平均。它还有个第二身份：FluidNinja "低清模拟、高清渲染"的魔法就是它——128×128 的模拟结果，显示时在每个像素位置插值，免费放大到 4K，而流体本来就没有像素级锐利的细节，视觉几乎无损。

v = Σ wᵢ·vᵢ  (wᵢ 随距离衰减，Σwᵢ = 1)
→ 去演示 2-1 勾"显示模拟网格"，看清 96×96 → 丝滑的差距
深入一层

把权重写开就是：v = (1−a)(1−b)·v00 + a(1−b)·v10 + (1−a)b·v01 + ab·v11，其中 a、b 是落点到格线的比例。四个权重加起来恒等于 1 —— 这就是它"不凭空造质量"的原因（对比前向 splat 的权重和 ≠ 1）。

放大画面时硬件沿用的还是这四个权重，GPU 纹理单元（sampler）一个周期内完成，所以说"免费"。

A6

数值耗散Numerical Dissipation

插值 = 轻微的模糊，每帧都在磨掉小旋涡

要认识的敌人
A4 稳定性的代价 —— A9 就是来救它的

这不是 bug 而是格点方法的固有副作用：每次插值都丢一点点小尺度信息。宏观表现是流体越流越"糊"、小旋涡无声消失。别沮丧——它顺便免费提供了粘性（真解里最贵的一项），而且下一张卡片的算法专门收拾它。

→ 去演示 2-1 投放染料方块，看直角几分钟内变圆
深入一层

耗散强度和分辨率直接挂钩：同一笔细节，在 96×96 网格里占 3 个格子，在 256×256 里占 8 个格子 —— 被同样次数的插值模糊后，高分辨率的细节"相对更耐磨"。这就是为什么专业流体模拟提升观感的第一件事永远是加分辨率，而不是调参数。

数学上，双线性平均恰好等价于给场乘上一个微小的扩散算子 —— 所以说"粘性项被免费送了"并非修辞，是严格的等价。

A7

衰减Dissipation

每帧除以 (1 + d·Δt)，让流体"老去"

搬运 · 调味料
烟用大 d，墨用 0，水用极小 d

速度和染料若永不消减会越积越乱。最简单的"老去"：每帧除以一个略大于 1 的数。它不是物理，是美术参数——烟、墨、水的气质差异，一半来自这一个系数。

φ ← φ / ( 1 + d·Δt )
float decay = 1.0 + dissipation * dt;
fragColor = texture(uSource, coord) / decay;
→ 去演示 5-1 切换"烟 / 墨 / 水"预设对比
深入一层

换算成半衰期更直观：d = 0.6 时亮度减半约需 1.1 秒（烟感），d = 0 时永不衰减（墨），速度场的 d 通常比染料小 —— 风停了惯性还在，墨才有"余韵"。

用除法 (1+d·Δt) 而不是乘法 (1−d·Δt) 是刻意的：除法形式在任意 Δt 下都不会把值变成负数，又一个稳定性小设计。

第三组 · 让流体像流体 本组是灵魂

A8

涡度Curl / Vorticity

放一根小桨轮，它转不转、往哪转

测量
对邻居速度做差分就得到它

衡量一个格子"旋转强度"的标量：逆时针为正、顺时针为负、静止为零。它本身只是个测量，但它是下一张卡片（涡度约束）的输入，也是第 5 章速度视图里那些漂亮旋涡的数学实体。

ω = ∂u_y/∂x − ∂u_x/∂y
float L = texture(uVelocity, 左).y;
float R = texture(uVelocity, 右).y;
float T = texture(uVelocity, 上).x;
float B = texture(uVelocity, 下).x;
float vorticity = R - L - T + B;
深入一层

2D 涡度的物理意义：它等于一小片流体角速度的两倍。ω = 10 意味着这片水每秒转 5 弧度 —— 约一圈多。把它想成"每格的转速表"，第 5 章速度视图里那些色环就是它的可视化表亲。

注意代码取的是"邻居的垂直分量算左右差、水平分量算上下差"—— 旋转本来就该由"交叉方向"的速度差定义，直觉上：右边的风往上吹、左边的风往下吹，中间必然在逆时针转。

A9

涡度约束Vorticity Confinement

给每个快被磨平的旋涡配一个"扶它的教练"

反耗散补丁
数值耗散偷走的能量，这里主动还回去

先算涡度 ω 的梯度——它指向"附近哪里转得更凶"；然后沿这个方向补一把与旋转方向一致的力，人为把能量还给快被耗散吃掉的涡。电影游戏界的经典补丁（Fedkiw 1996）。ε 就是你拉的"涡度强度"滑块：0 = 蜂蜜，40 = 湍流。

F = ε · ( ∇|ω| × ω )  →  u ← u + Δt·F
vec2 force = 0.5 * vec2(abs(T) - abs(B), abs(R) - abs(L));
force /= length(force) + 1e-4;      // 归一化：只定方向
force *= curl * C;                    // 乘强度和本地涡度
velocity += force * dt;               // 还给旋涡
→ 去演示 3-1 把滑块从 0 拉到 40 对比
深入一层

代码里有一行神秘的 force.y *= -1.0;：∇|ω| × ω 的叉积在"y 向上"的数学坐标系里方向正确，而屏幕/纹理坐标系 y 向下 —— 不翻转的话所有旋涡会被反向加速，越转越死。坐标系约定是图形代码里最常见的隐形坑。

ε 并非越大越好：它还给系统的能量是"凭空"的，拉太高会看到旋涡违反直觉地自我增强、出现病态抖动。20~35 是安全区。

A10

散度Divergence

给每个格子记账：净流出必须为零

记账
三种格子：源、汇、合法

把格子想成账本：四面八方的流入减流出必须恰好等于零。你随手"拍"出来、被平流搬过一圈的速度场，几乎不可能刚好满足——于是需要接下来两张卡片把它熨平。（代码里贴边格子的法向速度会取反：墙不可穿透，撞墙的账也要算对。）

∇·u = 0  （不可压缩条件）
float div = 0.5 * (R - L + T - B);  // 中心差分记账
→ 去演示 4-1 的散度视图：红=源 蓝=汇，投影开启时斑点一帧消失
深入一层

这里用的中心差分（R−L 而不是 R−C）是二阶精度的：误差与格子尺寸的平方成正比，格子减半误差降为四分之一 —— 这就是为什么网格加密对投影质量的收益是超线性的。

边界处理"法向速度取反"（如左边界的 u 取 −u）等价于"墙外有一面镜像的风往回吹"，这样墙边的账天然是平的，不需要单独的边界 pass。

A11

压力泊松方程 · Jacobi 迭代Poisson / Jacobi

"取邻居平均、再减我的账"，全屏刷 N 遍

心脏
膨胀户被解出压力低谷 → 被拉回；被挤户解出压力峰 → 被撑开

数学上把账算平等价于解一个泊松方程 ∇²p = ∇·u——但真解是百万级联立方程，游戏不等它，用 Jacobi 迭代：给每个格子一个傻瓜更新规则，反复搓到接近。压力就是把速度场熨平到不可压缩的那只熨斗，迭代次数 = 熨多少下。两个工程技巧：热启动（上一帧的压力留 80% 当初始猜测，收敛快得多）和敢少迭代（"接近不可压缩"视觉上已经是水：1 次 → 果冻，40 次 → 锋利）。

p ← ( p左 + p右 + p上 + p下 − div ) / 4  × N 遍
float pressure = (L + R + B + T - divergence) * 0.25;
→ 去演示 4-1 拖"压力迭代"滑块 1 → 60，现场看质感
深入一层

Jacobi 不是唯一的解法，只是最好写、最好并行的：Gauss-Seidel（用刚算出的新值当邻居）收敛快一倍但相邻像素有依赖、并行不干净；共轭梯度、多重网格（multigrid）能把迭代次数从几十降到个位数 —— FluidNinja 这类商业资产在这层的优化深度是核心竞争力之一。

收敛慢的根本原因：Jacobi 每轮信息只传一格，而压力的"影响范围"是全局的。多重网格的思路就是先在粗网格上把大范围趋势算平，再回细网格修细节。

A12

梯度减除 · 投影Gradient Subtract

u ← u − ∇p，账就平了

收针
算散度 → 解压力 → 减梯度，三步合称"投影"

压力算出来了，最后一步：逆着压力梯度修正速度。可以证明修正后的 u 散度恰好为零——整条"算散度 → 解压力 → 减梯度"流水线合称投影（projection），是这类流体"像水而不是像烟"的全部原因。

u ← u − ∇p  ⇒  ∇·u = 0 ✓
velocity.xy -= vec2(R - L, T - B);  // R/L/T/B 是压力采样
→ 去演示 4-1 关掉"压力投影"，看流体立刻"漏气"
深入一层

"任何速度场都能分解成一个无旋场和一个无散场之和" —— 这是数学上的 Helmholtz 分解。投影 u ← u − ∇p 做的事，就是减掉无旋部分、留下无散部分。所以这个步骤叫"投影"：把速度投影到"所有无散场"组成的子空间上。

为什么减 ∇p 减掉的恰好是无旋部分？因为任何标量场的梯度都没有旋度（∇×∇p ≡ 0）—— 数学早在 19 世纪就铺好路了。

第四组 · 自驱动 没人碰它也在动

A14

浮力Buoyancy

热轻于冷：温度越高，向上的力越强

火焰的发动机
温度场（复用染料 R 通道）每帧换一次升力

火焰、烟、热浪不需要交互：热空气密度低，自动获得向上的加速度，力正比于温度。配合底部持续"点火"和 dissipation 的冷却，火苗的形状、摇曳、顶端熄灭全部自发涌现。再加一层随时间和高度变化的水平摆动（两个 sin 叠加），就是风的错觉。

u.y += β · T · Δt   u.x += w · T · sway(t) · Δt
→ 去演示 6-1 调浮力和摇曳滑块
深入一层

严格的热浮力还含一项"环境温度扣减"（T − T₀），避免全场均匀受热时整体漂移；烟囱效果的经典变体是再加一个重量项（u.y −= w·density），温度往上顶、染料往下坠 —— 烟云的翻滚感就来自这两股相反的力。

黑体色带（暗红→橙→黄→白）是物理正确的近似：理想黑体的辐射颜色只随温度变化，铁匠看火色判温度用了几千年。

A15

持续注入 / 排出Inflow / Outflow

把 splat 从"点一下"变成"每帧都来"，就是一条河

河流的发动机
第 4 章的投影保证注入的水"有处可去"

河流的内核朴素得惊人：边界处每帧 splat 一个恒定方向的速度（上游），另一侧做阻尼吸能 + 禁止倒流（下游）。配合圆形区域内速度清零的"石头"，投影会自动解出绕流，石头背后旋出成串涡街。FluidNinja Live Environment 的河流、熔岩、沼气，都是这套内核换色带、换参数。

u(边界, 每帧) += v_in   ·   石头内: u = 0
→ 去演示 6-2 调流速、开关石头
深入一层

进水口用 splat 而不是直接写纹理，是为了保持管线的"加法一致性"（力永远叠加，不硬覆盖）；真正的产品实现会在边界格子上直接施加 Dirichlet 条件（固定速度），数学上更干净。

石头背后的周期性涡旋叫卡门涡街（Kármán vortex street），斯特劳哈尔数描述它的脱落频率 —— 桥梁工程师要提防它，游戏美术却爱死它：免费、自然、还带节奏感。

第五组 · 输出 从模拟到画面

A13

法线生成Normal from Height

把染料当高度，梯度的反方向就是水面朝向

输出
法线 × 光源 = 高光、深浅 —— 一片"水"诞生

引擎的水需要法线贴图做高光和折射，而模拟只给了颜色密度。解法：把染料亮度当"高度"，高度梯度的反方向就是表面朝向，再套最简单的光照（漫反射 + Blinn-Phong 高光）。这就是 FluidNinja 交给 Unity 渲染管线的核心素材之一——演示 5-1 的"水面法线"视图就是它的最小实现。

n = normalize( −∂h/∂x, −∂h/∂y, k )
vec3 n = normalize(vec3((hL - hR) * k, (hB - hT) * k, 1.0));
float diff = max(dot(n, L), 0.0);
col = 基色 * (0.45 + 0.62 * diff) + 高光;
→ 去演示 5-1 切"水面法线"视图或点"水"预设
深入一层

公式里的 k（本页代码用 16）是波纹陡峭度：k 越大，同样高度的染料边缘算出的法线越倾斜、高光越碎。引擎里的等价物是法线贴图的 strength/flatness 参数。

在 Unity 里接法：把这张法线 RT 接入 Lit 材质的 Normal Map 通道、高度接 Displacement，再让 FluidNinja 的投影器把整张材质贴到地形上 —— 水就从 2D 模拟"长"进了 3D 世界。
